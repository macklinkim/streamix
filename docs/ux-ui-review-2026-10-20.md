## 1. 판정과 범위

**종합 HOLD.** 방송실의 무확인 이탈에 따른 송출 종료, 텍스트 대비 부족, 좁은 랜딩 오류 화면의 하단 행동 잘림을 확인했다. 기존 회귀 검사 통과는 아래 신규 발견의 해소나 실방송 검증을 뜻하지 않는다.

| 평가           | 판정             | 근거                                                                           |
| -------------- | ---------------- | ------------------------------------------------------------------------------ |
| UI Finish-Gate | HOLD             | 버튼·안내 대비 부족, 좁은 오류 화면의 가입·둘러보기 접근 저하                  |
| 동작           | HOLD             | 송출 중 헤더 이동으로 종료, 채팅 읽기 위치 강제 이동, 장애를 인증 오류로 표시  |

### 환경과 권한

- 공개 배포: <https://streamix-web.vercel.app>. 실제 홈페이지→가입→로그인 이동, 빈 폼 제출, 키보드 조작, 비로그인 방송실 접근을 수행했다. 실제 가입·승인·차단·키 회전·방송은 수행하지 않았다.
- 로컬: `http://localhost:3000`, Windows, Next.js **15.5.26**, React **19.2.7**, Playwright Chromium **149.0.7827.55**, axe-core **4.14.0**. API·채팅·송출 연결은 모의 응답, 카메라는 Chromium 가짜 장치다.
- Git 기준: `abea6eb597f957dd1f4b1b6609de0a3faee638af` + 기존의 다수 미커밋 변경. 최신 방송실·인증 코드를 포함한 작업 트리를 검토했다. 이번 작업의 변경은 문서·지침·검증 산출물이다.
- 이전 배포 ID: `dpl_AeDUPv9WCdYGNnYSzsi3fKqHFttA`. [릴리스 기록](../outbox/releases/2026-10-20-ca2551c3.md)에 근거한다. 공개 화면의 주요 동작을 대조했지만 배포 파일과 현재 작업 트리의 바이트 일치는 검증하지 않았다. 보호 화면 발견은 **로컬 결과**다.
- 역할: 실제 비로그인 사용자; 로컬 모의 승인 사용자/방송자/관리자; 기존 회귀 검사의 모의 가입 대기·승인 결과. 실제 관리자·승인 계정의 종단 검증과 구분한다.
- 크기: 가입 화면 1920×1080, 768×1024, 375×667, 390×667, 1023/1024×1080, 320×667; 방송실 1920×1080·375×667; 랜딩 오류 375×667·320×568. 모든 화면을 모든 크기에서 검증한 것은 아니다.
- 실제 휴대전화, Safari/Firefox, NVDA/JAWS, 화면 확대 프로그램은 사용하지 못했다. 에뮬레이션을 실기기 검증으로 표기하지 않는다.
- 판정 원칙: 재현한 필수 문제는 FAIL, 성공한 개별 검사는 PASS, 미실행 항목은 NOT TESTED. 실험 화면 `/lab`은 NOT APPLICABLE. 필수 미검증이 있어 전체 PASS는 불가하다.

## 2. 제품·화면별 디자인 기준

Streamix의 주 사용자는 방송을 발견하고 영상과 채팅을 함께 보는 시청자, 송출 상태를 보며 채팅 참여자를 관리하는 방송자다. 최우선 객체는 실제 방송·재생·송출·연결 상태이며, 주요 행동은 시청 진입, 채팅 전송, 송출 시작·종료다. 가입 승인은 관리자 작업이다. 다크 테마와 보라색 브랜드는 유지하되 장식보다 상태 판별·오류 복구·송출 지속을 우선한다. 구독·팔로우·검색 같은 미제공 기능을 필수 요구로 추가하지 않는다.

## 4. 발견 사항과 개선안

### U01 — 헤더 이동으로 송출이 확인 없이 종료됨

- **P1 · 필수 · 동작/UI · 방송자.** 방송 진행 중 실수로 공통 탐색을 누르면 시청 중인 방송을 끊는다.
- 위치: `apps/web/components/site-header.tsx:30`, `apps/web/components/broadcast.tsx:89`, `:270`. 언마운트 시 정리는 필요하지만 이동 전에 이를 보호하는 장치가 없다.
- 재현: 로컬 승인 방송자 → `/studio/live` → 송출 시작 → 가짜 ingest 프레임 증가 확인 → 헤더 `스튜디오` 클릭.
- 기대: 방송실로 유지하거나, 이탈이 방송을 끝낸다는 확인 후 진행. 실제: `/studio`로 이동하고 소켓 종료, 확인 대화상자 없음.
- 증거: `results.json`의 `header studio navigation stops stream` (`closed=true`, `confirmationShown=false`), [진행 화면](assets/ux-ui-review-2026-10-20/studio-live.png), [이동 후](assets/ux-ui-review-2026-10-20/studio-settings.png).
- 최소 수정: 송출 중 헤더의 스튜디오는 현재 방송실로 연결하고, 다른 내부 이동·뒤로 가기·새로고침에는 송출 종료 안내를 일관되게 적용. 정리 코드를 제거하지 않는다. 방송 수명 전체를 영구화하는 대규모 재설계는 별도 결정이다.
- 통과 조건: 헤더·홈·뒤로 가기에서 취소하면 트랙·ingest 프레임 유지, 확인하면 정확히 한 번 종료. 새 탭 `내 방송 보기` 기존 통과도 유지.

### U02 — 주요 행동과 안내 텍스트 대비 부족

- **P1 · 필수 · UI/접근성 · 모든 역할. Serious. WCAG 1.4.3 Contrast (Minimum), AA.** 시력이 낮은 사용자가 행동·상태를 읽기 어렵다.
- 위치: `apps/web/app/globals.css:8`, `apps/web/components/site-header.tsx:57`, `apps/web/components/broadcast.tsx:316`, `apps/web/components/chat.tsx:187`, `apps/web/app/watch/[slug]/page.tsx:106`.
- 재현: 로컬 가입·홈·오프라인 시청·방송실을 열고 axe WCAG 태그 검사 및 화면 대조.
- 실제: 흰 글자 `#ffffff` / 보라 버튼 `#7c5cff` **4.34:1**, 사이드바 안내 `#71717b` / `#09090b` **4.12:1**, 오프라인 보조 문구 `#52525c` / `#18181b` **2.29:1**. 해당 작은 텍스트 기준은 **4.5:1**. 애니메이션 중 변동하는 노드 비율은 대표 수치에서 제외했다.
- 증거: [axe 원본](assets/ux-ui-review-2026-10-20/results.json)의 `color-contrast` 노드와 `failureSummary`, [오프라인 화면](assets/ux-ui-review-2026-10-20/watch-offline.png), [가입 화면](assets/ux-ui-review-2026-10-20/signup-375.png).
- 최소 수정: 작은 흰 글자 버튼에 충분히 어두운 보라 배경 사용, 본문·힌트용 회색을 별도 조정. 예를 들어 배경 `#6b4bf0`와 흰 글자는 계산상 약 5.40:1이나 실제 hover/focus/disabled·반투명 배경 조합을 다시 측정해야 한다. 브랜드 색 전체의 무조건 교체는 피한다.
- 통과 조건: 모든 적용 노드 4.5:1 이상, 큰 텍스트 3:1 이상; 색상 변경 후 14개 상태 재검사와 수동 대비 확인. disabled 예외를 일반 안내 문구에 적용하지 않는다.

### U03 — 좁고 낮은 랜딩 오류 화면에서 하단 행동이 잘림

- **P1 · 필수 · UI/접근성 · 첫 방문자. Serious. WCAG 1.4.10 Reflow, AA 관련 실패.** 가입·둘러보기의 포인터 접근이 막히며 작은 화면의 복구 경로가 약해진다.
- 위치: `apps/web/components/landing/landing-gate.tsx:84`의 고정·`overflow-hidden`과 본문 스크롤 잠금; 로그인 카드의 중앙 배치·고정 패딩 조합.
- 재현: 저장 상태 없는 로컬 375×667 → `로그인으로 바로 가기` → 빈 로그인 제출 → 320×568로 줄임.
- 기대: 내용이 길어지면 대화상자 내부에서 스크롤해 가입·둘러보기까지 접근. 실제: `그냥 둘러보기`의 y≈609.8, 높이 44px인데 뷰포트 높이는 568px; 화면 하단에서 잘린다. 정상 375×667에서는 버튼이 보이므로 정상 상태만으로 통과하면 놓친다.
- 증거: [320px 오류](assets/ux-ui-review-2026-10-20/landing-errors-320.png), [375px 오류](assets/ux-ui-review-2026-10-20/landing-errors-375.png), `results.json`의 `landing narrow error reflow`. Escape 닫기는 통과했다. 키보드 Tab으로 모든 잘린 행동을 회수할 수 있는지는 미검증이다.
- 최소 수정: 배경 스크롤 잠금은 유지하되 대화상자에 세로 스크롤을 허용하고, 작은 높이에서는 폼을 위에서부터 배치. 내부 컨테이너의 높이/패딩 조정과 함께 검사한다.
- 통과 조건: 320px 폭·568px 이하 높이, 오류 2개 및 서버 오류·소프트키보드 조건에서 포인터와 키보드로 모든 행동 접근; 400% 실제 확대도 추가 확인.

### U04 — 새 채팅이 과거 메시지 읽기 위치를 빼앗음

- **P2 · 필수 · 동작/UI · 시청자·방송자.** 질문·신고 대상 확인 중 새 메시지마다 최신 위치로 돌아간다.
- 위치: `apps/web/components/chat.tsx:103–105`의 메시지 변경 시 무조건 `scrollTo`.
- 재현: 로컬 방송실에서 긴 메시지 80개 수신 → 채팅 상단으로 스크롤 → 메시지 하나 추가 수신.
- 기대: 과거 내용을 읽는 동안 위치 유지, 최신으로 이동하는 별도 행동 제공. 실제: `scrollTop` **0→3364**로 이동.
- 증거: `results.json`의 `reading old messages interrupted`, [채팅 화면](assets/ux-ui-review-2026-10-20/chat-new-message.png). 키보드 포커스 강탈이나 실제 스크린리더 발화는 검증하지 않았으므로 그 결함까지 주장하지 않는다.
- 최소 수정: 갱신 직전 하단 근처인 경우에만 자동 추적. 나머지는 위치를 유지하고 새 메시지 수·최신 이동 버튼 제공. 200개 보관 한도로 앞 메시지가 제거될 때의 앵커도 확인.
- 통과 조건: 맨 아래에서는 자동 추적, 중간·상단에서는 연속 수신에도 읽기 위치 유지, 버튼으로 최신 이동. 방송자 관리 대상 선택도 유지.

### U05 — 로그인 서비스 장애를 잘못된 비밀번호로 표시

- **P2 · 필수 · 동작/오류 복구 · 로그인 사용자.** 사용자가 불필요하게 비밀번호를 바꾸거나 반복 입력하게 한다.
- 위치: `apps/web/app/login/page.tsx:42–49`. 승인 대기 이외의 모든 실패를 같은 문구로 처리한다.
- 재현: 로컬 `/auth/login`을 HTTP 503으로 모의 설정 → 형식에 맞는 이메일·테스트 비밀번호 → 로그인 제출.
- 기대: 서비스 연결 실패와 재시도 안내. 실제: `이메일 또는 비밀번호가 올바르지 않습니다.`
- 증거: `results.json`의 `login 503 feedback`, [서비스 오류 화면](assets/ux-ui-review-2026-10-20/login-service-error.png). 운영 서버에서 실제 503이 발생했다고 주장하지 않는다.
- 최소 수정: 401 자격증명, 403 승인 대기, 429 일시 제한, 네트워크/5xx 일시 장애를 기존 `AuthError` 기준으로 분리. 세부 서버 오류 원문은 그대로 노출하지 않는다.
- 통과 조건: 각 응답과 네트워크 거부를 주입해 안내·초안 유지·중복 제출 방지·재시도 확인. 랜딩 로그인도 같은 분류 적용 여부 확인.

### U06 — 슬로우모드 설정 후 현재 적용 값이 사라짐

- **P2 · 필수 · UI/상태 판별 · 방송자.** 무엇이 적용 중인지 다시 확인하기 어렵다.
- 위치: `apps/web/components/chat.tsx:167–175`. 변경 직후 `event.target.value = ""`로 초기화한다.
- 재현: 로컬 방송실 → 슬로우모드 10초 선택 → 성공 안내 확인.
- 기대: 적용 중 `10초`가 지속 표시. 실제: 성공 문구는 있으나 선택기는 다시 `설정 선택`이며 값은 빈 문자열이다.
- 증거: `results.json`의 `slowmode value after successful setting`. 모의 API 성공은 실제 서버 정책 집행의 증거가 아니다.
- 최소 수정: 성공한 값을 제어 상태로 유지하고 실패 시 이전 값 복원. 재입장까지 보장하려면 서버에서 읽을 현재 상태가 있는지 먼저 확인하고 API 확장을 별도 결정한다.
- 통과 조건: 10초→실패한 30초 변경→해제에서 표시와 실제 응답 일치. 재입장·다른 관리자 변경의 동기화는 별도 통합 검사.

### U07 — 모바일 관리자 헤더에서 단어가 글자 단위로 분절됨

- **P3 · 선택 개선 · UI · 관리자.** 탐색의 빠른 식별이 어려우나 버튼 기능 자체는 차단되지 않았다.
- 위치: `apps/web/components/site-header.tsx:16–47`, `:68` 주변 고정 높이·간격·축소 가능한 항목.
- 재현: 관리자 모의 세션으로 375×667 `/admin` 접속.
- 실제: `승인`이 두 줄, `스튜디오`와 `로그아웃`도 글자가 여러 줄로 나뉜다.
- 증거: [관리자 375px](assets/ux-ui-review-2026-10-20/admin-pending-375.png).
- 최소 수정: 역할별 모바일 헤더 간격·로고 폭·명칭을 조정하고 단어 분절을 방지. `whitespace-nowrap`만 넣어 가로 넘침을 만드는 수정은 피한다.
- 통과 조건: 320/375/390px 관리자·일반 사용자·비로그인 조합에서 읽히는 이름, 터치 간격, 가로 넘침 없음.

### U08 — 모바일 방송 관리에서 채팅 확인과 송출 조작이 멀어짐

- **P3 · 선택 개선 · 제품 UI · 방송자.** 모바일에서 미리보기 아래로 채팅을 적층해 송출 조작·시청자 메시지를 왕복 스크롤해야 한다. 접근 불가 결함으로 단정하지 않는다.
- 위치: `apps/web/app/studio/live/page.tsx:102`, `:106`의 그리드와 채팅 높이.
- 증거: [모바일 준비 상태](assets/ux-ui-review-2026-10-20/studio-ready-375.png). 667px 첫 화면에서는 채팅 메시지·전송 영역이 아래로 밀린다. 실기기 소프트키보드는 미검증이다.
- 개선: 송출 중 접을 수 있는 미리보기와 항상 찾을 수 있는 종료·채팅 이동 행동을 검토. 작은 화면에 데스크톱 두 열을 억지로 유지하지 않는다.
- 통과 조건: 실제 휴대전화에서 송출 유지하며 새 메시지 확인→사용자 선택→제재→종료를 완료. 필요한 스크롤·초점 이동을 관찰해 최종 배치를 결정.

## 5. 접근성 결과

판정 기준은 W3C의 [1.4.3 Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)과 [1.4.10 Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) 설명을 확인했다(2026-10-20). 이번 표본 검사와 전체 적합성 평가는 구분한다.

자동 검사는 [run.cjs](assets/ux-ui-review-2026-10-20/run.cjs)에서 `wcag2a,wcag2aa,wcag21a,wcag21aa,wcag22aa` 태그로 실행했다. 14개 화면/크기/상태에서 `color-contrast` 실패가 확인됐다. 같은 원인이 화면마다 반복되므로 발생 노드 수를 서로 다른 결함 수로 세지 않았다. 랜딩·송출 상태에는 `incomplete` 노드도 남아 있으며 자동 통과로 처리하지 않았다.

필수 재개 조건: NVDA+Chrome 또는 적절한 실제 스크린리더 환경에서 커튼→인증→방송 탐색→시청/채팅과 방송실/관리자 완전한 프로세스를 수행한다. 제목·읽기 순서·오류 연결·새 메시지 과다 발화·선택한 관리 대상·상태 공지를 기록하고, 실제 확대·터치·자막 검사를 추가한다.

## 6. 유지할 장점과 우선순위

유지할 것:

- 방송 설정과 실제 송출·채팅 공간의 분리. `내 방송 보기` 새 탭을 열어도 가짜 캡처 트랙과 프레임이 유지되는 기존 검사가 통과했다.
- 홈의 빈 목록과 조회 실패 구분, 재시도 행동. 실제 빈 상태가 정상적으로 보였고 오류가 빈 방송 목록으로 바뀌지 않았다.
- 가입 전 관리자 승인 조건 안내와 가입 후 대기 안내. 회귀 검사상 무조건 자동 로그인하지 않는다.
- 이메일 저장과 자동 로그인을 구분하고 비밀번호를 저장하지 않는 구조. 실제 저장·삭제는 모의 로그인 결과와 함께 검증했다.
- 키 재발급 전 확인, 복사 실패 안내, 채팅 제재 실패 안내. 기존 회귀의 복구 동작을 유지한다.
- 작은 폭의 가입 폼 가로 넘침 방지, 네이티브 입력·선택기와 명확한 라벨. 장식 목적의 재설계는 필요 없다.

실행 우선순위:

1. **U01/U03**: 송출의 우발적 종료와 신규 진입의 행동 잘림을 먼저 막는다. 확인 취소·오류 내용 증가·좁은 화면 회귀를 추가한다.
2. **U02**: 실제 색상 조합을 고치고 axe·수동 대비 재검사. 외형 선호보다 접근성 기준이 우선이다.
3. **U04/U05/U06**: 채팅 읽기 위치, 로그인 장애 복구, 현재 제재 상태 표시를 수정하고 실패 조건을 함께 검사한다.
4. **U07/U08**: 역할별 모바일 헤더와 방송실 조작 거리를 개선한다. 실제 휴대전화 관찰 후 배치를 확정한다.
5. 운영 준비: 이전 릴리스 기록에는 관리자 초기 설정이 미완료로 남아 있다. [가입 승인 운영](signup-approval.md)에 따라 운영자가 설정한 뒤 전용 가입 신청 계정으로 승인→로그인 전체 검사를 수행한다. 이번 리뷰에서 관리자 수를 재조회하거나 임의 승격하지 않았다.
6. 전용 계정·실미디어·실기기·스크린리더로 §3/§5의 NOT TESTED를 해소하고 재판정한다.

전체 PASS 조건: 필수 발견 U01–U06 수정과 재현 검사 통과, 실제 서비스의 시청·송출·채팅·승인 흐름 검증, 접근성 필수 미검증 해소. 선택 개선 U07/U08의 미반영만으로 필수 PASS를 막지는 않되 제품 결정과 남은 한계를 기록한다.

## 7. 실행 기록과 한계

### 실제 실행

```powershell
# 저장소 루트
agent-mem --version
agent-mem status
agent-mem paths
agent-mem doctor
agent-mem search 'Streamix 방송 관리' --limit 3
agent-mem show M1
pnpm --filter @streamix/web dev

# 기존 검사: apps/web 디렉터리에서 최종 재실행
node node_modules/@playwright/test/cli.js test e2e/ux-regressions.spec.ts e2e/landing-visibility.spec.ts e2e/login-options.spec.ts e2e/studio-management.spec.ts --reporter=json

# 별도 증거 수집: 저장소 루트, 로컬 axe 파일 경로 지정
node docs/assets/ux-ui-review-2026-10-20/run.cjs outbox/axe-core-4.14.0.min.js
```

- 최종 기존 검사: **종료 0, 27 passed, 0 failed, 0 skipped**, 약 34.4초. [최종 원본](assets/ux-ui-review-2026-10-20/regressions.json).
- 첫 전체 실행: 26 통과·1 실패. 신규 `/studio/live` 진입이 기본 5초 assertion 내 완료되지 않았다. 단독 재실행 5/5, 전체 재실행 27/27 통과. 냉시작 컴파일 지연 가능성은 있으나 원인을 확정하지 않았다. [최초 실행 기록](../outbox/ux-review-regressions-2026-10-20.json)은 pnpm의 후행 메시지가 있어 순수 JSON이 아니다.
- 증거 수집 최종 실행: **종료 0**, [스크립트](assets/ux-ui-review-2026-10-20/run.cjs)·[결과](assets/ux-ui-review-2026-10-20/results.json). 스크립트는 제품 결함을 고치는 코드가 아니라 관찰 결과를 저장하는 QA 도구이며, HOLD 상태에서도 관찰이 완료되면 종료 0이다.
- 임시 axe 확보 과정에서 pnpm dlx 구문·npm 모듈 검색 경로 시도는 실패했다. npm 캐시에 받은 공식 `axe-core` 4.14.0의 `axe.min.js`를 찾아 사용했다. 제품 package.json·lockfile에 새 의존성을 추가하지 않았다. 재실행 시 같은 버전의 로컬 파일을 준비한다.
- 수집 스크립트 초안은 변경된 건너뛰기 문구와 Next route announcer의 alert 중복 때문에 실패했다. 실제 문구와 `main` 범위로 수정 후 성공했다. 해당 도구 오류를 서비스 결함으로 집계하지 않았다.
- 로컬 콘솔에는 비로그인 `/auth/refresh` 401과 의도적으로 주입한 로그인 503의 리소스 오류가 남았다. 결과 JSON에 보존했고 **콘솔 오류 0**을 주장하지 않는다. 수집한 5xx는 주입한 503 한 건이며, 의도하지 않은 5xx는 관찰되지 않았다. 운영 전체 네트워크 무오류를 뜻하지 않는다.
- 개발 서버에는 워크스페이스 루트 추정·다중 lockfile 경고가 있었다. 제품 UX 결함으로 집계하지 않았다.
- `agent-mem`은 M1 저장·조회·검색을 검증했고, 완료 요약도 프로젝트 기억에 저장한다. 자세한 운영 절차와 자동 수집 한계는 [agent-memory.md](agent-memory.md)에 기록한다.
